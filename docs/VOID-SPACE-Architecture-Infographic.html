Four Core Design Principles

Executive Summary
① Exactly One Writer Per Boundary

Only the API writes domain state. Only the Worker holds a signing key. Only Postgres holds the system of record. Nothing else may become a second source of truth.

② Tenant Isolation at the Database

Row-level security is forced on 18 tables. The runtime role physically cannot read across tenants — not by convention, by grant. A misconfigured connection fails at boot.

③ Slow Work Never Blocks a Request

AI classification, IPFS pinning, Blender conversion, chain transactions and notifications are all queued jobs with documented retry policies — never inline in the request.

④ Trust Is Verifiable

Content is addressed by hash (CID). Licences are on-chain ERC-721 tokens. Every state change is in an append-only audit ledger that records chain receipts alongside application events.

Safety Critical
🔐
Tenant isolation is the platform's most safety-critical property. A leak would expose one customer's unreleased product models to another. It is enforced in the database, not trusted to application code.

Three Database Roles
void_app
API + Worker runtime. Full DML, but every tenant-scoped table has FORCE ROW LEVEL SECURITY. Cannot cross tenants even with a hand-written query.

draft ──submit──▶ pending ──decision──▶ approved ──publish──▶ published (terminal)
                   │                        │
                   ├─▶ needs_manual_review ─│─ assessor decides
                   ├─▶ revision ──resubmit──┘
                   └─▶ rejected ──new version
Key Transition Rules
⚠
Comment mandatory for rejected and revision. The creator must be told what to fix.
⚠
Self-review blocked. An assessor may not review their own asset — removes the self-approval hole.
✓
published is terminal. A takedown revokes the licence flag; the token is never burned.
✓
Deletion limited to draft, pending, revision, rejected. Anything approved or beyond is protected.
⚠
Illegal transitions return INVALID_STATUS_TRANSITION (409). The state machine is the contract.
ℹ
Only pending and needs_manual_review appear in the review queue — it is a worklist, not a report.

Async Job Platform — 6 BullMQ Queues

Queue Attempts Backoff Concurrency On Exhaustion
ai-enrichment 2 fixed 2s 2 One retry with stricter prompt → needs_manual_review
ipfs-pin 3 exponential 2s 4 Version marked pinStatus: failed, visible in console
blender-optimize 2 exponential 5s 1 Failure in job status; original version untouched
chain-license 3 exponential 3s 2 Job failed; asset stays approved — never silently published
xr-publish 3 exponential 3s 2 Retried; does not affect licence validity
notify 2 fixed 1s 4 Best-effort; a lost notification never blocks the workflow
📊
Jobs mirrored to Postgres. Every enqueued job has a row in jobs. The console polls SQL — no Redis tooling needed to diagnose stuck work.
🛡️
Structural guarantees: Nothing sits between markActive and the try-block. A missing subject is an obsolete job, not a crash. Clearing Redis cannot corrupt application state.

Security Posture

Concern Control
Transport🔒TLS 1.2+ only, HSTS, HTTP redirected to HTTPS at the edge
Brute Force🛡Rate limits at nginx per client (50 r/s API, 100 r/s general) + per-endpoint limits on auth
Credential Storage🔒bcrypt cost 12 for passwords; API keys and refresh tokens stored as hashes with visible prefix only
Session Theft🛡Short-lived access tokens, rotating refresh tokens, reuse detection revokes session family, HttpOnly + Secure + SameSite cookies, refresh cookie path-scoped to /api/v1/auth
Authorisation🔒Single permission matrix, re-resolved per request from database, enforced in preHandler
Tenant Isolation🛡Forced RLS on 18 tables + boot-time assertion that refuses to run with a bypassing role
Upload Abuse🔒Extension AND MIME validation plus magic-byte sniffing, 200 MB ceiling, streamed to per-tenant staging path
Enumeration🛡Assets a caller may not see answer 404, not 403 — the API cannot be used to probe another workspace
Chain Key Exposure🔒No signing key in the API environment; only the worker holds it; job payloads carry identifiers only
Supply Chain🛡Zero external Solidity dependencies; audited dependency set; lockfile committed

Non-Functional Requirements → Mechanism

NFR-PERF.2
Uploads up to 200 MB without exhausting memory
Streamed multipart to disk; worker streams to IPFS one chunk at a time
NFR-PERF.4
Repeat IPFS reads served from cache
nginx gateway cache; safe because content is immutable (CID = hash)
NFR-REL.1
Externally-dependent work must not block requests
6 queues with documented retries; nothing slow runs inside a request
NFR-REL.2
A chain outage must not corrupt asset state
Promote-to-published only after mint receipt exists in hand
NFR-SEC.3
Upload validation beyond the file extension
Extension + MIME + magic-byte sniffing + 200 MB ceiling
NFR-SEC.5
Tenant isolation must be verifiable, not assumed
Forced RLS on 18 tables, boot-time role assertion, isolation tests
NFR-SCAL.1
Worker throughput must be tunable per queue
Per-queue defaultConcurrency, overridable per worker via env
NFR-SCAL.2
API and worker must scale independently
Stateless API + separate worker process; shared state = Postgres/Redis/IPFS only
NFR-OBS.1
Every action must be attributable
Correlation id on every request; append-only audit ledger with request id, tx hash, IPFS CID
NFR-PORT.1
Chain portability
EVM-only contract, viem typed client, chain chosen by configuration alone
